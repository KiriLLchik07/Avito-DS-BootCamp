# Детекция ботов по событиям Avito

Решение тестового задания Avito DS BootCamp. Код находится в [solution.ipynb](solution.ipynb); исходная реализация метрики - в [metric.py](metric.py).

## Структура проекта для запуска

```text
Avito-DS-BootCamp/
│
├── data/                         # Данные задания; скачать отдельно, в Git не входят
│   ├── train.csv                  # Размеченные куки
│   ├── test.csv                   # Куки для прогноза
│   ├── events.csv                 # События из распакованного events.csv.gz
│   └── sample_submission.csv      # Шаблон ответа
├── artifacts/                    # Создаётся ноутбуком; экспериментальные прогнозы
├── solution.ipynb                 # Основное воспроизводимое решение
├── quickstart.ipynb               # Исходный пример организаторов
├── metric.py                      # Официальная метрика
├── optuna_xgb.sqlite3             # 40 готовых испытаний XGBoost
├── optuna_catboost.sqlite3        # 32 готовых испытания CatBoost
├── submission.csv                 # Лучший проверенный ответ (CatBoost)
├── requirements.txt               # Точные версии прямых зависимостей
├── pyproject.toml                  # Описание окружения для uv
├── uv.lock                        # Зафиксированное дерево зависимостей
└── README.md                      # Описание и инструкция по запуску
```

Пути указаны относительно корня проекта: именно из него нужно запускать `solution.ipynb`. Базы Optuna лежат в корне и позволяют не повторять подбор параметров.

## Задача и данные

Для каждой `cookie_id` нужно предсказать вероятность того, что её суточная история принадлежит известному сервису автоматизированного сбора данных (`target = 1`), а не человеку (`target = 0`). Основная метрика - максимальный **Precision при Recall ≥ 70%** на скрытом тесте. Порог выбирает проверяющая система; в ответе нужны оценки от 0 до 1.

В `train.csv` содержатся 11 091 кука, из них 899 положительных; в `test.csv` - 4 909. `events.csv` содержит действия пользователей, из которых нужно самостоятельно построить поведенческие признаки. При расчёте используются только события внутри индивидуального окна наблюдения каждой куки. Полное описание и исходные файлы опубликованы на Stepik.

## Подход и этапы

1. Загружаем данные, отбираем события внутри окон, удаляем полные дубликаты. Простой baseline из [quickstart.ipynb](quickstart.ipynb) служит точкой сравнения.
2. Строим 110 признаков по частотам действий, просмотрам и поиску, времени суток, паузам и сессиям, разнообразию интересов, платформе, User-Agent и координатам указателя. Пропуски и категориальные значения обрабатываются до обучения.
3. Проверяем модели по времени начала окна: **A** - 10-12 апреля, **B** - 13-16 апреля, **C** - 17-19 апреля 2026 года. Каждый раз обучение использует только более ранние окна. C многократно применялось для сравнения гипотез, поэтому его нельзя считать независимым финальным тестом.
4. Сравниваем CatBoost, LightGBM и XGBoost, подбираем параметры XGBoost и CatBoost с помощью Optuna. Проверяем дополнительные блоки и сокращённые наборы признаков. Отдельно обучаем локальную нейросеть [TabM](https://github.com/yandex-research/tabm) с числовыми эмбеддингами.
5. Переобучаем выбранный CatBoost на всех размеченных куках. Его прогноз - корневой [submission.csv](submission.csv). Экспериментальный прогноз TabM сохраняется отдельно в `artifacts/submission_tabm.csv` и получил 0.80750 на Stepik.

Локальная метрика Precision@Recall≥0.70:

| Модель                                     |          A |          B |          C |
| ------------------------------------------ | ---------: | ---------: | ---------: |
| Baseline                                   |          - |     0.0967 |     0.1062 |
| CatBoost после исправления признаков UA/OS |     0.7407 |     0.6944 |     0.7278 |
| Выбранный CatBoost после Optuna            | **0.7547** |     0.7068 |     0.7386 |
| XGBoost после Optuna                       |     0.7767 |     0.7220 |     0.7273 |
| TabM                                       |     0.7207 | **0.7250** | **0.7417** |

TabM немного улучшил B и C, но уступил CatBoost на A. Усреднение нескольких seed и смешивание моделей не дали устойчивого прироста. Поэтому подтверждённым итоговым вариантом остаётся CatBoost.

## Воспроизведение

Нужны Python 3.12 и `uv`. Из корня проекта установите зафиксированные зависимости:

```powershell
uv sync --locked
```

Положите исходные файлы в `data/`: `train.csv`, `test.csv`, `sample_submission.csv` и распакованный `events.csv` из архива задания (`events.csv.gz`). Папка `data/` не входит в Git. Откройте `solution.ipynb` из корня проекта, выберите интерпретатор `.venv` как ядро и выполните ячейки по порядку. Seed равен **42**. CatBoost обучается на CPU; TabM использует CUDA при наличии совместимой видеокарты, иначе CPU. При первом запуске подбор Optuna использует базы Optuna из корня проекта или создаст их там и может занять длительное время.

Ноутбук создаёт корневой `submission.csv` с двумя колонками `cookie_id,score` в порядке `data/sample_submission.csv`. Сейчас в нём **4 909 уникальных ID** и допустимые оценки от 0 до 1. Весь код работает локально, без внешних API. Для сдачи нужны этот CSV, ноутбук и краткое описание подхода; по условиям задания ссылка на код должна быть доступна проверяющему.
